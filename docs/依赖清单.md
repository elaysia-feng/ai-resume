# 依赖清单（部署用）

> 生成时间：2026-10-24
> 适用版本：当前仓库 `main`（desktop 形态 + 单体化 + SQLite 化 + 去向量库之后）
>
> **一句话结论**：这是一个 **Electron 桌面端项目**，不是网页项目。
> 桌面端**不需要装任何外部中间件**（无 MySQL / Redis / RabbitMQ / Qdrant / Elasticsearch / Milvus）。
> 数据、任务队列、checkpoint 全部落在本地 SQLite 文件；唯一的网络依赖是 **LLM API**。
>
> **部署形态**：只有 3 个需要运行的东西 —— Electron 应用（用户看到的窗口）、
> Java 后端（:8080）、Python 后端（:8000）。`desktop/renderer/` **不是独立部署的服务**，
> 它是 desktop 复用的渲染层源码目录，见第 4 节。

| `@types/node`（dev） | ^24.10.1 | Node 类型 |

`desktop/` 复用 `desktop/renderer/` 的渲染层，`npm run build` 内部会跑 `build:renderer` → `build:main` → `build:stage`。
打包 Windows 安装包：`npm run package`（产物在 `desktop/release/`）。

### ⚠ 关键：必须先装 `desktop/renderer/` 的依赖

`desktop/vite.config.mts` 把 Vite 的 `root` 指向 `./renderer`，**渲染层源码直接用 `desktop/renderer/src`，
不复制任何 Vue 代码**。因此：

- `desktop/package.json` 的 devDependencies **只有** `vue` / `vite` / `esbuild` / `typescript` 等构建工具，
  **不含** `vue-router` / `pinia` / `axios` / `gsap` / `html2canvas` / `jspdf` / `@vueuse/motion`；
- 这些运行时依赖由 Vite 按 `root` 向上查找 `node_modules` 解析 ⇒ **落在 `desktop/renderer/node_modules`**。

⇒ **只 `cd desktop && npm ci` 就去 `npm run build`，会因为解析不到 `vue-router` 等包而失败。**

正确顺序：

```powershell
cd frontend && npm ci     # 先装渲染层运行时依赖
cd ..\desktop && npm ci   # 再装 Electron 工具链
npm run build             # 产物输出到 ../desktop/renderer/dist
```

> `build:renderer` 的输出目录是 `desktop/renderer/dist`（`base='./'`，保证 `file://` 加载时静态资源路径是相对路径），
> 会覆盖 `desktop/renderer/` 自己的 `npm run build` 产物。两者可以互相覆盖，用哪边都行。---

## 5.1 桌面端安装包里装了什么（自包含应用）

用户装完 exe 就能用，**机器上不需要装 Java、Python、Node，也不需要任何中间件**。
后端运行时由 CI 打进安装包：

| 组件 | 打包方式 | 产物 | 体积 |
| --- | --- | --- | --- |
| Electron 主进程 + 渲染层 | electron-builder | `AI Resume Forge.exe` + `resources/app.asar` | ~100 MB |
| Java 后端（含 JRE） | `jpackage --type app-image` | `resources/backend/ai-resume-backend/` | ~150 MB |
| Python AI 运行时 | PyInstaller `--onedir` | `resources/python/ai-resume-api/` | ~116 MB |
| 建表脚本 | maven resources | 打进 jar 的 `db_schema/schema.sql` | 启动时自动建表 |

**本地复现这两步**：

```powershell
# Java：jpackage 生成自带 JRE 的 app-image
cd backend\java
mvn -B clean package
New-Item -ItemType Directory -Force -Path build\stage
Copy-Item target\ai-resume-forge-backend.jar -Destination build\stage
jpackage --type app-image --name ai-resume-backend --input build\stage `
  --main-jar ai-resume-forge-backend.jar --dest build\jpackage --app-version 0.1.0
# （--dest 目标目录已存在时 jpackage 会报错，先删掉旧的）

# Python：PyInstaller 打成独立 exe
cd ..\python
uv sync --extra dev --python 3.14
uv run python scripts\build_desktop_bundle.py --clean
```

> `jpackage` 产出的 runtime **不含 `java.exe`**（app-image 只有 jvm.dll），
> 必须走它生成的 `ai-resume-backend.exe` 启动。
> `scripts/build_desktop_bundle.py` 不要收集 `mcp` 子模块：`mcp.cli` 依赖未安装的 `typer`，
> `collect_submodules('mcp')` 会直接 `sys.exit(1)` 让打包失败。

### 安装后的目录布局

```
{安装目录}/                      ← NSIS 装到哪就放哪
├── AI Resume Forge.exe
├── resources/
│   ├── app.asar
│   ├── backend/ai-resume-backend/    ← Java 后端（自带 JRE）
│   └── python/ai-resume-api/         ← Python AI 运行时

```

## 7. 环境变量

### 7.1 仓库根 `.env`（Java 后端读；`backend/java/.env` 优先）

复制 `.env.example` 为 `.env` 后填写：

```ini
JWT_SECRET=change-me                 # 必填，JWT 签名密钥
MAIL_USERNAME=                       # 邮箱账号
MAIL_PASSWORD=                       # 邮箱授权码
PYTHON_AGENT_BASE_URL=http://localhost:8000
INTERNAL_AGENT_SERVICE_TOKEN=change-me   # Java 与 Python 必须一致
DB_FILE=./data/ai_resume.db          # SQLite 业务库
STORAGE_ROOT=                        # 头像存储根目录，留空用「用户主目录/Documents/AI-Resume-Forge」

AGENT_RESUME_RUN_STREAM=agent.resume.run
AGENT_INTERVIEW_RUN_STREAM=agent.interview.run
AGENT_RUN_RESULT_STREAM=agent.run.result
AGENT_RUN_DLQ_STREAM=agent.run.dlq

MINIMAX_BASE_URL=https://api.minimaxi.com/anthropic
MINIMAX_MODEL=MiniMax-M3.1-Flash
MINIMAX_MAX_TOKENS=4096
MINIMAX_ANTHROPIC_API_KEY=            # 必填
```

> `MINIMAX_ANTHROPIC_API_KEY` 的属性名是 `anthropic-api-key` 而不是 `api-key`：
> Spring 的 relaxed binding 会把 `minimax.api-key` 映射到系统环境变量 `MINIMAX_API_KEY`，
> 而操作系统环境变量优先级高于 `.env`，旧 key 会把 `.env` 里能用的 key 盖掉（调 Anthropic 兼容端点会 401）。

### 7.2 `backend/python/.env`（Python 后端读）

复制 `backend/python/.env.example` 为 `backend/python/.env` 后填写：

```ini
LLM_PROVIDER=deepseek                # deepseek / mimo
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_CHAT_MODEL=deepseek-chat
# 或 LLM_PROVIDER=mimo 时用 MIMO_API_KEY / MIMO_BASE_URL / MIMO_CHAT_MODEL

JAVA_INTERNAL_BASE_URL=http://localhost:8080
INTERNAL_AGENT_SERVICE_TOKEN=change-me   # 必须与根 .env 一致
AGENT_TASK_DB_PATH=F:/.../backend/java/data/ai_resume.db   # 必须与 Java 指向同一个业务库
CHECKPOINT_DB_PATH=F:/.../backend/python/data/checkpoints.db
AGENT_RESUME_RUN_STREAM=agent.resume.run     # 必须与根 .env 一致
AGENT_INTERVIEW_RUN_STREAM=agent.interview.run
AGENT_RUN_RESULT_STREAM=agent.run.result
AGENT_RUN_DLQ_STREAM=agent.run.dlq
AGENT_RESUME_WORKER_GROUP=agent-resume-worker
AGENT_INTERVIEW_WORKER_GROUP=agent-interview-worker
AGENT_QUALITY_LLM_SCORING=true
```

> `AGENT_TASK_DB_PATH` 是 Java 投递 / Python worker 消费**共用的同一个 SQLite 文件**，
> 路径必须完全一致，否则消息投递不到消费者。

## 8. 部署顺序（Windows / PowerShell）

```powershell
# 0) 建库：把 db_schema/schema.sql 执行到 SQLite 文件（Java 启动时只建目录，不建表）
python -c "import pathlib,sqlite3; db=pathlib.Path('backend/java/data/ai_resume.db'); db.parent.mkdir(parents=True,exist_ok=True); c=sqlite3.connect(db); c.executescript(pathlib.Path('backend/java/db_schema/schema.sql').read_text(encoding='utf-8')); c.commit(); c.close(); print('schema applied ->',db)"

# 1) Java 后端
mvn -B -f backend\java\pom.xml clean package
java -jar backend\java\target\ai-resume-forge-backend.jar   # :8080

# 2) Python 后端
cd backend/python
uv sync --extra dev --python 3.14
uv run uvicorn src.app.main:app --host 127.0.0.1 --port 8000

# 3) 前端依赖（桌面端构建渲染层也要用到，必须先装）
cd frontend && npm ci

# 4) 桌面端（开发模式，复用 frontend 渲染层）
cd ..\desktop && npm ci && npm run dev
```

只跑前端 dev（不开桌面端）时，第 4 步可跳过；只跑桌面端时，第 3 步**不能跳**。

建库脚本执行后应输出 **14 张表**（13 业务表 + `agent_stream_group`）。
可用 `python bench\verify_sqlite_schema.py` 复验 schema 与约束（该脚本建在临时目录，不影响业务库）。
